# DCACI-Bert

Code for image-text retrieval on Flickr30K and MS-COCO.

The model combines three parts. A region-based visual encoder and a BERT text
encoder produce the base embeddings. A concept-level branch builds a graph over
visual concepts, propagates information along it and fuses the result back into
both modalities through a gated module. A frozen CLIP branch adds a global
semantic view of the image and, optionally, its patch tokens.

## Requirements

Python 3.8 or newer, one CUDA device.

```
pip install -r requirements.txt
```

`torchtext` has to match the installed `torch`, for example `torch==1.13.1`
with `torchtext==0.14.1`. It is used for the GloVe table that initialises the
text concept embeddings.

## Data

`--data_path` points at a directory with the following layout.

```
{data_path}/
  id_mapping.json                     image id -> file name
  flickr30k-images/                   raw images, only for clip_source=online
  f30k_precomp/                       or coco_precomp/ for MS-COCO
    train_ims.npy                     region features, N x R x 2048
    train_caps.txt                    one caption per line
    train_ids.txt                     image id per line
    dev_ims.npy, dev_caps.txt, dev_ids.txt
    test_ims.npy, test_caps.txt, test_ids.txt
  Concept_annotations/
    concepts_300.pkl                  concept vocabulary, keys text_concepts
                                      and visual_objects
    adj_matrix_300.pkl                concept co-occurrence matrix
    similarity_matrix_300.pkl         concept similarity matrix
    f30k_concepts_word2vec_300.pkl    generated by gen_concept_features.py
    f30k_concepts_visual2vec_300.pkl  generated by gen_concept_features.py
```

The concept annotations are the only dataset-specific input that is not derived
from the raw images and captions. `--num_attribute` selects the suffix, so a
vocabulary of a different size simply uses matching file names.

### Concept embeddings

```
python gen_concept_features.py \
    --data_path /path/to/data/f30k \
    --data_name f30k \
    --bert_path /path/to/bert-base-uncased
```

The text side averages GloVe vectors, the visual side averages pooled region
features over all training images annotated with the concept, and both need a
GPU pass over the training split. Existing files are skipped, so the command is
safe to repeat. `--skip_visual` builds only the text side.

### CLIP features

With the default `--clip_source online` the raw image is decoded and encoded by
a frozen CLIP model during training, and no feature files are needed. To avoid
that cost, pre-compute the features once and switch to `--clip_source npy`.

```
python gen_clip_features.py --data_path /path/to/data/f30k \
    --clip_model_path /path/to/open_clip_pytorch_model.bin --splits train dev test

python gen_patch_features.py --data_path /path/to/data/f30k \
    --clip_model_path /path/to/open_clip_pytorch_model.bin --splits train dev test
```

Both scripts write next to the region features and keep a `--verify` mode that
compares a re-encoded sample against the official model output, so a wrong
checkpoint or preprocessing step is caught before a long run starts. The patch
features are only read when `--use_patch_fusion 1`.

## Training

```
python train.py \
    --data_path /path/to/data/f30k \
    --data_name f30k \
    --dataset f30k \
    --bert_path /path/to/bert-base-uncased \
    --logger_name runs/f30k_main \
    --num_epochs 30 --batch_size 32 --seed 1
```

`--logger_name` is also where checkpoints are written. The log goes to
`{logger_name}/train.txt` and to stdout, and the resolved options are saved
alongside so that `eval.py` can rebuild the exact model.

Two settings matter for a clean run. The script holds a lock per `logger_name`,
so a second launch on the same directory exits instead of competing for the GPU
and truncating the log; disable it with `--single_instance 0`. It also checks
free GPU memory before the first step, derived from the device size or set with
`--min_free_gpu_mb`.

`--seed` fixes Python, NumPy and Torch. Repeating a run with different seeds
gives the mean and standard deviation reported in the paper.

## Evaluation

```
python eval.py \
    --data_path /path/to/data/f30k \
    --dataset f30k \
    --model_path runs/f30k_main/model_best.pth
```

Flickr30K is evaluated on the single test split, MS-COCO on the 5-fold 1K and
5K protocols. `--save_results 1` additionally writes the similarity matrix, and
the image and caption embeddings are exported next to the checkpoint for the
visualisation script (`--save_embs_dir` overrides the location).

## Options that change the architecture

| Option | Default | Effect when set to 0 |
| --- | --- | --- |
| `--use_concept_graph` | 1 | Drops the whole concept branch and keeps the encoder features. CGIG, CMGA and the KL prior all depend on the graph, so they become inactive too. |
| `--use_concept_guided_graph` | 1 | Disables concept-guided instance graph fusion and keeps the instance-level relation only. |
| `--use_cmga` | 1 | Disables the cross-modal graph topology alignment loss. |
| `--use_clip_fusion` | 1 | Disables the CLIP global branch. |
| `--use_patch_fusion` | 0 | The patch branch is off by default and needs the patch features on disk. |

The graph weights influence the retrieval path only when the corresponding
inference switch is on. By default `--use_graph_inference 0` and
`--use_instance_inference 0`, which means the graph and the sample-level module
act as training-time structural regularisers and `emb_v` / `emb_t` are the
evaluated features. Set them to 1 to retrieve with the enhanced features; both
respect a warm-up window so that early validation does not use an untrained
branch.

## Notes

The CUDA allocator is configured at import time in `train.py` and `eval.py`
(`max_split_size_mb`). This only affects how memory is carved up, not any
computed value, and can be overridden by exporting `PYTORCH_CUDA_ALLOC_CONF`
before the run.

On a machine without fork-based multiprocessing, keep `--workers 0`. The cached
feature arrays are large and pickling them to worker processes is slower than
reading them in the main process.
